# UI_MAP — 화면·용어·데이터 정본 빠른 지도

화면을 고치기 전 **어느 화면인지, 어떤 정본을 읽는지** 빠르게 확인하는 인덱스다. 기능 상세와 변경 이력은 각 도메인 문서를 따른다.

## A. 화면 지도

| 공식 화면명 | 사용자 진입점 | 실제 파일·함수 | 역할 |
|---|---|---|---|
| 내 보드 | 헤더의 내 보드 | `assets/js/kakao-auth.js` `openProfilePanel()` | 로그인 회원의 보드 컨테이너 |
| 내 프로필 보드 정본 | 내 보드 > 프로필 보드 | `openProfilePanel('taste')` / `_buildTasteInnerHtml()` | 평소 플레이·모임 참여 페이스·게임 취향 3단·어려운 게임을 보여주는 상세본 |
| 프로필 보드 미리보기 카드 | 내 보드 안 프로필 보드 카드 | `_tasteCardSummaryHtml()` | 모임원 목록 카드와 같은 핵심 프로필 요약: 자기소개·주 취향/난이도·참여 가능 빈도/때·게임 수. 차이는 내 보드 안 배치와 `프로필 보드 ›` 진입이다. |
| 모임원 프로필 페이지 | 동호회 > 모임원 프로필 | `pages/club/club-intro.html` | 모임원 프로필 목록과 작성 진입점 |
| 모임원 프로필 작성 위저드 | 모임원 프로필 페이지의 작성·수정 | `club-intro.html` `openWizard()` | 6단계 자기소개 입력·저장. 2단계 평소 플레이, 3단계 모임 참여 페이스, 4단계 게임 취향·어려운 게임 |
| 모임원 목록 카드 | 모임원 프로필 페이지의 각 회원 | `club-intro.html` `loadIntros()` | 프로필 보드 미리보기 카드와 같은 핵심 프로필 요약. 차이는 다른 모임원을 비교하는 목록 배치·닉네임·`프로필 자세히 보기 ›` 진입이며, 상세 정보는 내 프로필 보드 정본에서 확인한다. |
| 플레이 기록 정본 | 기록 입력·목록 | `pages/game/game-reviews.html` / `assets/js/game-reviews.js` | 기록 조회·작성·수정의 원 화면 |
| 플레이 기록 embed | 홈/내 보드에서 기록 열기 | `game-reviews.html` embed URL / `game-reviews.js` `initHub()` | 부모 화면 안에서 여는 기록 정본의 임베드 진입 |
| 기록 보드 | 내 보드 > 기록 보드 | `kakao-auth.js` 기록 서브시트 | 내 기록·통계 요약 |
| 모임 보드 | 내 보드 > 모임 보드 | `openProfilePanel('meeting')` | 실제 다가오는 모임·참여 등록·최근 참여. 프로필성 모임 참여 페이스는 노출하지 않음 |
| 홈 코티지 모임 미리보기 | 홈의 코티지 모임 영역 | `index.html` / `assets/js/index-page.js` | 날짜별 모임 상태의 홈 요약 |
| 날짜 모임 조율 | 홈/플래너의 날짜 선택 | `assets/js/day-detail.js` `openDateMeetingModal()` | 한 날짜의 모임 현황·인원 조율·참여자별 상세 |
| 수집 보드 | 내 보드 > 수집 보드 | `kakao-auth.js` 수집 서브시트 | 좋아요·궁금해요 등 개인 수집 요약 |
| 게임도감 | 내 보드 수집 흐름 또는 게임 화면 | `kakao-auth.js` 도감 섹션, 게임 데이터 소비처 | 보유 게임/플레이 기반 도감 |

## B. 화면 유형 정의

- **정본**: 모든 해당 정보를 확인·수정하거나 원 데이터로 이동할 수 있는 상세 화면. 예: 내 프로필 보드 정본, 플레이 기록 정본.
- **요약본 1**: 같은 기능의 내 보드 안 압축 카드. 예: 프로필 보드 미리보기 카드.
- **요약본 2**: 여러 사람을 비교·탐색하는 목록용 카드. 예: 모임원 목록 카드.
- **embed**: 정본을 부모 화면 안에서 열기 위한 임베드 진입 방식. 독립된 별도 데이터 정본이 아니다.
- **목록 카드**: 반복 목록의 한 항목. 데이터 전체를 담지 않으며 정본 또는 상세 진입점을 제공한다.

## C. 주요 데이터 정본 지도

| 도메인 | 정본 | 핵심 필드·계약 |
|---|---|---|
| 회원 프로필·게임 취향 | `member_intros` + `profile_hardest_games` | `preferred_game_types`·`game_type_range`·`avoid_game_types`, `preferred_game_depths`·`game_depth_range`·`avoid_game_depths`; 주 취향은 범위의 부분집합. 어려운 게임은 별도 정본 `profile_hardest_games` |
| 회원 공개 기본 정보 | `member_intros` | `nickname`, `location`, `join_sources`, 빈도, 평소 플레이 `usual_play_days/times`, 모임 참여 가능 `available_days/times`, 시계탑 선호, `expectation` |
| 계정 공통 프로필 | `profiles` | 계정 식별, 사진, 한줄소개 `bio`, 활동 누적, 대표 업적·칭호. `avoid_tags`·`preferred_game_depths`는 새 설문 정본이 아닌 레거시 컬럼 |
| 좋아하는 게임 | `game_likes` | 사용자별 좋아요 게임 |
| 해보고 싶은 게임 | `game_curious` | 사용자별 관심 게임 |
| 플레이 기록 | `game_play_records` | 기록의 게임 ID·일시·참여자·평가 등 |
| 날짜별 모임 참여 | `meeting_votes`, `meeting_vote_games` | 날짜별 가능 시간·판 의도·게임 |

## D. 모임원 프로필 명칭 규칙

- 게임 유형·난이도·가장 어려웠던 게임을 포함하는 정식 섹션명은 `게임 취향`이다. 가장 어려웠던 게임이 이 안에 있어도 `게임 취향과 경험`으로 확장하지 않는다.
- 평소 플레이 일정: 위저드는 `평소 플레이 요일` / `평소 플레이 시간대`, 프로필 보드는 `주로 플레이하는 때`를 쓴다.
- 모임 참여 일정: 위저드는 `참여 가능한 요일` / `참여 가능한 시간대`, 프로필 보드는 `참여 가능한 때`를 쓴다.
- 게임 유형 preference layers: 위저드는 `주 취향 게임 유형` / `즐기는 게임 유형 범위` / `꺼리는 게임 유형`, 프로필 보드는 `주 취향` / `즐기는 범위` / `꺼림 유형`을 쓴다.
- 게임 난이도 preference layers: 위저드는 `주로 즐기는 난이도` / `즐기는 난이도 범위` / `꺼리는 난이도`, 프로필 보드는 `주 난이도` / `즐기는 범위` / `꺼림 난이도`를 쓴다.
- 자기소개: 위저드는 `자기소개`, 프로필 보드는 `코티지에서 함께 게임할 때`를 쓴다.

위저드는 입력 의미를 명확히 하기 위해 풀어쓰고, 프로필 보드는 결과를 빠르게 훑을 수 있도록 짧게 쓴다. 위 차이는 의도된 명칭 차이이므로 임의로 한쪽 표현으로 통일하지 않는다. 양쪽에서 같은 일반 명칭은 이 규칙에 열거하지 않는다.

## E. 혼용 금지·주의 용어

- `프로필 보드`를 단독으로 쓰지 않는다. **내 프로필 보드 정본** 또는 **프로필 보드 미리보기 카드**를 명시한다.
- `미리보기`를 단독으로 쓰지 않는다. 무엇의 미리보기인지 명시한다.
- `세션`을 단독으로 쓰지 않는다. 브라우저 세션·분석 세션·플레이 세션처럼 수식한다.
- `sub-session`은 현재 공식 UI·데이터 용어가 아니다.
- `내 보드`는 보드 컨테이너, `내 프로필 보드 정본`은 그 안의 프로필 상세 화면이다.
