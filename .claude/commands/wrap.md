# 세션 종료 = 요약 작성이 아니라 상태 압축

⏱ **언제**: **"세션 종료"를 보고하기 전에** 아래를 자동 수행하고, 필요한 정리와 재검사까지 끝낸 뒤에만 종료를 선언한다. 단 사용자가 종료 절차를 **가정형으로 묻기만 한 경우엔 실행하지 말고 절차만 설명한다**(질문은 실행 명령이 아니다 — D-11).

1. **닫힌 항목은 PROJECT_STATE에서 지운다.** 완료 목록·커밋 목록·세션 회고를 거기 넣지 않는다.
2. 잃으면 안 되는 **기술적 판단은 도메인 문서 한 곳**에만.
3. **목표·종료 조건·다음 원자 작업**만 갱신한다.
4. 사용자에게는 완료 요약을 **말하되 문서에 복사하지 않는다.**

🔍 **검사 문장**: 여러 건을 닫은 세션이면 **PROJECT_STATE의 줄 수는 줄어야 한다.** 늘었다면 새로 열린 작업이나 필수 판단이 무엇인지 대고, 못 대면 압축한다.

> **사건(2026-07-20)**: "누락없이 정리해"를 **"빠짐없이 §0에 적기"**로 읽고 닫은 5건을 22줄로 늘어놨다. **거의 전부가 도메인 문서·git log에 이미 있었다.** 같은 사실이 두 곳에 있으면 다음 세션엔 "어느 쪽이 최신이지"가 된다. **누락 없음 = 제자리에 한 번 남기고 나머지를 지우는 것**이지 전부 복사가 아니다.
